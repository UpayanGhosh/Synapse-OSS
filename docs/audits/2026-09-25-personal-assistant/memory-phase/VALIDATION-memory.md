# Dynamic personal memory: implementation and validation

This phase connects verified person identity, raw conversation episodes, bounded profile projection, scoped recall, and accepted assistant replies to the existing chat runtime. It keeps the existing SQLite memory database and V2 observation queue. It does not migrate unowned legacy personal memory or provide shared household profiles.

## Delivered behavior

- Channel DMs derive a person from the server-normalized channel and sender; only configured `identityLinks` merge people. `dmScope=main` is partitioned by canonical person for short history, cache, and task serialization. Groups use group-only scope. An authenticated installation-token API call uses `local-api-owner`; an API without configured auth has no personal owner, regardless of caller `user_id`, `session_key`, or forged identity fields.
- Inbound user text is stored as an idempotent, user-authored episode before reply paths, including early spawn/reminder paths. The episode retains speaker, source key, visibility, source conversation time and capture time. A delayed replay uses the persisted inbox receipt. A phrase such as “last week” remains source text; `occurred_at` does **not** claim the incident happened at that time.
- Personal observations retry through the existing V2 durable queue. The gateway owns one lifecycle-managed memory pump. The extractor can propose typed confirmed facts and allowlisted explicit or tentative relationship style; the entire payload is evidence-validated before one short transaction applies facts, profile changes, and observation completion. Raw episodes remain recallable when enrichment fails. New typed facts carry `source_episode_id`; older NULL-source rows are preserved but excluded from personal prompts. A late older source cannot replace a newer correction.
- Person/group ownership is filtered in SQLite before ranking. The local FastEmbed provider is selected when the embedding setting is auto; a remote provider is used only when explicitly selected. Valid episode vectors are stored with model fingerprint and dimensions in the same DB; query embedding runs once per recall. Zero, nonfinite, wrong-dimension, and unavailable embeddings fall back to lexical matching. This fallback will miss some paraphrases.
- Full and casual prompts receive a small scoped evidence budget. Native `query_memory`, dual cognition, subagent snapshots, scoped SBS, and base prompt loading do not fall back to the old global personal corpus. Current explicit relationship style beats activated inference; a user's current-turn style request beats both. Tone and verbosity map through a small fixed enum; unrecognized values remain descriptive evidence but do not become style instructions. Core identity and tool rules stay separate. Legacy USER/MEMORY and learned global profile files are excluded; canonical operational documents remain.
- Assistant replies are separate role-tagged evidence linked to the triggering user episode. Channel output is recalled only after persisted channel acceptance; pending/failed output is hidden. Outbox metadata permits restart reconciliation when memory projection fails after a successful send, without resending. Direct API replies are labelled `returned` after successful response construction, which is **not** proof the client received them. Assistant text never becomes a user fact.
- Provenance-backed fact corrections retain immutable support history. For A to B to C, older evidence points to current C. A pure obsolete claim and its assistant echo are omitted from active recall; an episode that also contains an unrelated incident remains available with a structured correction label. The prompt renderer keeps the complete label before raw text, truncates raw text only, and omits an item whose correction labels exceed its tier budget.
- `/new` still archives/rotates short conversation history, and compaction remains. Interactive transcripts no longer feed ownerless legacy vector/KG/personal mining.

Behavioral RED was captured before the corresponding changes for scoped cognition/global graph leakage, native memory tool leakage, USER/MEMORY prompt leakage, cross-person sessions, ingress-before-early-return capture, generic API principal spoofing, scoped SBS, channel/direct reply provenance, ownerless archive mining, fact/projection atomicity, late correction, embedding paraphrase/fallback, prompt fact quarantine, persistent style precedence, immutable fact support and mixed-incident correction history. The final correction formatter had three behavioral REDs: long evidence, multiple labels, and label-before-raw budget. Luna's independent outbox review found and covered accepted-receipt projection/restart recovery. An earlier reminder phase startup-order correction preceded its structural regression; that exception is recorded in the main audit `VALIDATION.md`.

This existing pinned target includes the otherwise unavailable gateway imports; on this Windows host it required elevated filesystem access.

A final run of that same 26-file set under the target reported **109 passed, no skips**, including the actual FastAPI lifespan with fake channel/router boundaries, processing a queued scoped observation and stopping the pump cleanly. This supersedes an earlier partial 25-file run. The target required elevated access to its existing pinned dependencies on this Windows host. It reported three deprecation warnings. No external channel message was sent. Touched prompt-source/test Ruff, Python compileall, and `git diff --check` passed after the formatter change; independent review found no scoped P0/P1 blocker. The private reference assistant was unavailable for behavioral parity comparison.

## Limits and next proof

These tests establish durable ownership, atomic projection, prompt wiring, and recovery with synthetic model/provider/channel fixtures. They do not establish that a live LLM consistently extracts every useful preference or talks naturally over months. The isolated real gateway target lacked FastEmbed, so actual default semantic recall was unavailable there; the semantic path passed with a deterministic provider fixture, while lexical fallback remained active. No automatic migration of legacy unowned data was attempted. Shared-couple consent, personalized scheduled commentary, and external MCP memory endpoint access control remain later work. Unknown identity intentionally gets generic behavior. A future longitudinal live-model evaluation should measure relevant recall, false recall, correction obedience, tone fit, and overlong replies across A/B users and restarts before claiming the intended humanlike experience.

The repo-required `synapse_context_sync.bat` was attempted after implementation but stopped at its first offline graph update because the external uv cache denied access (`os error 5`). It did not reach graph status, risk scan, or MemPalace mining. Code and test evidence above are from the current repo files, not that external cache.
