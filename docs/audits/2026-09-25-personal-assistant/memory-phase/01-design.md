# Dynamic personal memory: approved slice

Decision owner: root architect. Status: implementation contract approved; source changes follow behavioral RED tests.

## Scope

Use the existing SQLite memory database as the source of truth. Add an owner-scoped episodic and relationship projection in `personal_memory.py`; preserve existing typed user facts as the fact source of truth. Capture every user turn before generating a reply with speaker, conversation, stable source key, person, visibility, original or received UTC time, recorded time, and provenance. Do not invent event dates or emotional certainty. An incident or inside joke remains a raw episode even when enrichment fails. The new projection must be idempotent on replay.

Derive person identity independently of persona. A direct channel DM uses its channel/peer identity, with only explicitly configured operator identity links allowed to unify channels. Group context is separate and receives no private episode or profile. Missing or ambiguous identity fails closed for personalization. Direct API calls with a configured and validated installation token receive server-owned principal `local-api-owner`; body `user_id` and `session_key` only partition conversation history. Without configured token, direct API remains generic. The API is a single-owner installation surface, not a multiuser identity service. Internal route/channel code supplies `PersonMemoryContext(person_id, conversation_id, visibility)`; request JSON cannot supply trusted context.

Keep Synapse's base identity stable. Person-specific relationship style and explicit preferences live in separate, versioned state with evidence and correction priority; do not write user data into shared persona files. Extend the SBS accessor to `get_sbs_for_target(target, *, person_id=None)` and cache scoped instances by `(target, person_id)`. Scoped instance data lives under the configured Synapse data root in a SHA-256 person directory and safe persona directory; its runtime workspace is isolated. The old persona singleton remains for generic system paths but never receives personal writes. Corrections suppress stale derived entries from active recall while preserving original events as clearly historical.

Personal recall filters person and visibility before ranking, uses a small prompt budget even in `casual_light`, and abstains when evidence is weak. Never fall back to ownerless personal vector, graph, or permanent-profile records after a scoped miss/error. Keep generic system knowledge and bot instructions separate. Existing unowned personal corpus stays quarantined until a proven migration. Derived episode embeddings, provider fingerprint, dimension, and status live in the same SQLite projection. Use the existing provider interface directly, with an explicit local default or explicitly configured network provider; reject zero, nonfinite, wrong-dimension, or model-mismatched vectors. Batch pending episode embeddings asynchronously through the existing durable observation scheduling; embed a query once per recall, then rank owner-filtered candidates by cosine plus lexical evidence. If embedding is unavailable, raw episodes remain and lexical fallback is labelled as limited.

The public module contract is an immutable `PersonMemoryContext(person_id: str | None, conversation_id: str, visibility: Literal['private', 'group'] = 'private')` and `PersonalMemoryStore(db_path)`. Private storage is keyed by `person:<person_id>`; group storage by `group:<conversation_id>`. `person_id` in a group identifies the speaker only. Invalid private identity has no personal write/read; groups have no relationship profile in this slice. The server-only resolver is `resolve_person_memory_context(*, channel_id, peer_id, conversation_id, chat_type='direct', identity_links=None, api_authenticated=False, origin='channel')`. API origin uses `local-api-owner` only when the installation token was configured and validated. No request body field can claim a principal.

`capture_episode(context, *, source_message_id, content, occurred_at, recorded_at=None)` returns a stable episode ID or `None` for ineligible context/content. The unique key is `(owner_key, source_message_id)`; a retry with incompatible content, conversation, or speaker raises. Aware datetime or offset ISO 8601 inputs normalize to UTC; naive/invalid inputs fail. `recall(context, query, *, limit=3)` returns immutable `RecalledEpisode` records with episode ID, person ID, conversation ID, source message ID, content, occurred/recorded UTC times, visibility, and finite score. Candidate ownership is filtered before ranking and irrelevant queries abstain.

`get_relationship(context)` returns `{'version': int, 'preferences': dict, 'inferred': dict}` (empty/version 0 without valid private scope). `apply_relationship_update(context, updates: dict[str, str], *, source_episode_id: str, evidence: str)` accepts only explicit tone, verbosity, humor, formality, and address_as preferences, each at most 120 characters. The source episode must share private owner, and evidence must occur in its user text. Same episode/payload is idempotent; a changed explicit value increments version once and supersedes the active value while retaining update history. Cross-owner, group, unsupported, or ungrounded updates fail. Model-inferred updates remain a separate, later validated path. Existing typed facts use canonical person ID for new writes; no duplicate fact table is introduced. An async service layer may enrich the projection around this synchronous store without changing these contracts.

## Required acceptance

- A's explicit playful preference, small incident, and inside joke survive restart and appear only when relevant to A; B's calm profile stays separate.
- A correction wins over a stale preference; irrelevant prompts abstain; original time and source survive recall.
- Group prompts exclude private memory. Duplicate ingress does not duplicate episodes. Extractor failure leaves the raw episode usable.
- Casual prompt assembly includes a bounded relevant personal evidence slot. Legacy ownerless rows are not adopted or exposed.
- Existing 28 reminder/inbox/outbox tests stay green. Synthetic prompt tests establish plumbing, not humanlike dialogue quality.

Implementation proceeds test-first. No migration of legacy ownerless records and no live-account actions are part of this slice.

## Root refinements during implementation

- `occurred_at` records the user's **conversation turn time** (provider event time when verified, otherwise durable inbox receipt time). It is not the date of an incident described in the message. `recorded_at` records SQLite capture time. A late replay must preserve the original receipt time.
- Direct private conversations use a stable person namespace even if legacy `dmScope=main` would put different senders in one session. Explicit identity links may unify the same verified person. Legacy transcripts remain intact but are not silently adopted. Groups have their own conversation scope. Anonymous requests use no shared server history.
- Default recall excludes support episodes superseded by explicit corrections; `include_history=True` can show them labelled with the replacing source. Tentative inferred style needs two independent, evidence-grounded episodes with confidence at least 0.7 each. Explicit preference overrides inference. Assistant-authored replies are stored separately from user evidence and only become recallable after channel acceptance (or direct API return); they never support user facts or profile changes.
- Every interactive prompt path, including anonymous and group routes, quarantines unowned legacy documents, vector/KG lookup, recent-session reminder, global affect, shared USER/MEMORY documents, and shared SBS learned profile. Canonical operational INSTRUCTIONS/CODE/SOUL/CORE/IDENTITY/TOOLS/AGENTS remain. The native `query_memory` tool and subagent snapshot use the same scoped store; external legacy MCP memory endpoints remain a separate access-control limitation.
- Raw user episode capture is synchronous before reply and before early skill/reminder/spawn returns. Background enrichment uses the existing V2 durable observation queue with bounded retries, validated relationship updates, and batch episode embeddings. Automatic embedding selection is local FastEmbed only; an explicitly selected network provider is allowed. Failure leaves the raw episode usable and cannot trigger an unscoped fallback.
- Scheduled reminder execution remains generic in this slice because its current execution adapter does not pass a verified actor/audience pair into the chat pipeline. Reminder delivery reliability is preserved; personalized proactive commentary needs a later trusted mapping.
