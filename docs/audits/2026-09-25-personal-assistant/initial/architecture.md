## Most consequential gaps

1. **Shared memory has no user boundary in retrieval (highest priority, conditional on more than one human using an install).** Channel sessions and immediate structured facts are keyed by session, but `MemoryEngine.query` accepts no user/session ID and LanceDB filters only `hemisphere_tag`: [pipeline_helpers.py](../../../../workspace/sci_fi_dashboard/pipeline_helpers.py#L1404), [memory_engine.py](../../../../workspace/sci_fi_dashboard/memory_engine.py#L188), [memory_engine.py](../../../../workspace/sci_fi_dashboard/memory_engine.py#L268). Session ingestion also writes one shared vector table with no identity metadata: [session_ingest.py](../../../../workspace/sci_fi_dashboard/session_ingest.py#L391), [vector_store/lancedb_store.py](../../../../workspace/sci_fi_dashboard/vector_store/lancedb_store.py#L39). The shared SQLiteGraph nodes/edges have no owner key: [sqlite_graph.py](../../../../workspace/sci_fi_dashboard/sqlite_graph.py#L55). Permanent profile and recent archived-session SQL likewise select by filename only: [chat_pipeline.py](../../../../workspace/sci_fi_dashboard/chat_pipeline.py#L2048), [chat_pipeline.py](../../../../workspace/sci_fi_dashboard/chat_pipeline.py#L361). On a single-person install this is a relevance issue; with multiple people it can become cross-user disclosure.

2. **Most conversational moments are not available as long-term memory until background ingestion.** The immediate path writes only patterns recognized by deterministic fact distillation, while general dialogue goes to transcripts and awaits `/new` or a 50-message/6-hour flush: [user_memory.py](../../../../workspace/sci_fi_dashboard/user_memory.py#L563), [pipeline_helpers.py](../../../../workspace/sci_fi_dashboard/pipeline_helpers.py#L161), [pipeline_helpers.py](../../../../workspace/sci_fi_dashboard/pipeline_helpers.py#L1040). Existing session history can cover recent turns, but cross-session semantic/KG recall is delayed. The ingestion task is fire-and-forget, so durability of transcript capture is stronger than proof of completed indexing: [pipeline_helpers.py](../../../../workspace/sci_fi_dashboard/pipeline_helpers.py#L1093).

3. **Recall precision and prompt budgeting are inconsistent.** Frontier and mid policies set no minimum relevance score, so the nearest memories are injected even if weakly related: [prompt_tiers.py](../../../../workspace/sci_fi_dashboard/prompt_tiers.py#L61), [memory_engine.py](../../../../workspace/sci_fi_dashboard/memory_engine.py#L392), [chat_pipeline.py](../../../../workspace/sci_fi_dashboard/chat_pipeline.py#L273). For a casual, fast, non-reflective turn, the compact policy sets `memory_limit=0`, graph off, and one history turn: [chat_pipeline.py](../../../../workspace/sci_fi_dashboard/chat_pipeline.py#L815), [chat_pipeline.py](../../../../workspace/sci_fi_dashboard/chat_pipeline.py#L838). Permanent profile docs, SBS persona, and sometimes special recent-session context still survive, but ordinary dynamic episodic snippets do not. This makes everyday conversation less likely to demonstrate memory, even though retrieval already ran.

4. **Event timing and emotion are too coarse for grounded personal recollection.** Normal transcript turns contain only role/content; `append_message` adds no timestamp: [pipeline_helpers.py](../../../../workspace/sci_fi_dashboard/pipeline_helpers.py#L1251), [pipeline_helpers.py](../../../../workspace/sci_fi_dashboard/pipeline_helpers.py#L1501), [multiuser/transcript.py](../../../../workspace/sci_fi_dashboard/multiuser/transcript.py#L155). Session chunks receive the ingestion date, not the original event times: [session_ingest.py](../../../../workspace/sci_fi_dashboard/session_ingest.py#L354), [session_ingest.py](../../../../workspace/sci_fi_dashboard/session_ingest.py#L267). Affect tags are deterministic and assigned to the whole chunk of user text, while prompt hints summarize a mood without tying it to a specific original turn: [memory_affect.py](../../../../workspace/sci_fi_dashboard/memory_affect.py#L313), [memory_affect.py](../../../../workspace/sci_fi_dashboard/memory_affect.py#L331), [memory_affect.py](../../../../workspace/sci_fi_dashboard/memory_affect.py#L508). Structured facts do carry `first_seen`/`last_seen`, but those mark capture/update, not the conversation event.

5. **Embedding failure can silently create unusable memories.** If no provider exists or embedding throws, `get_embedding` returns an all-zero vector rather than failure: [memory_engine.py](../../../../workspace/sci_fi_dashboard/memory_engine.py#L161). `add_memory` treats that as an embedding, may upsert it into LanceDB, and marks the document processed; it also returns `stored` when LanceDB upsert itself fails: [memory_engine.py](../../../../workspace/sci_fi_dashboard/memory_engine.py#L487). As `query` searches LanceDB, a successful SQLite receipt need not mean the fact is retrievable. This is a conditional reliability risk, not proof that this installation currently lacks embeddings.

6. **Short replies are guided, not guaranteed.** The code mirrors tiny/short messages, but has no length constraint when the user's message exceeds 30 words: [chat_pipeline.py](../../../../workspace/sci_fi_dashboard/chat_pipeline.py#L2174). Default style tells the model to mirror user detail: [style_policy.py](../../../../workspace/sci_fi_dashboard/style_policy.py#L50). This is a product policy choice that can cause long answers in everyday use.

The requested parallel retrieval agent is not the current default path: retrieval occurs first and is passed as cached data to dual cognition. The deep cognition path can run present analysis and cached recall concurrently: [chat_pipeline.py](../../../../workspace/sci_fi_dashboard/chat_pipeline.py#L2067), [chat_pipeline.py](../../../../workspace/sci_fi_dashboard/chat_pipeline.py#L2119), [dual_cognition.py](../../../../workspace/sci_fi_dashboard/dual_cognition.py#L319). This is primarily a latency/design difference; the user-visible guarantee is grounded recall before reply.

## Repair sequence and proof to demand

First add owner identity to vector documents, graph facts, permanent profile docs, and archived-session retrieval; test two users with overlapping people/topics and show no cross-user result. Next make memory write/index status explicit and retryable, and persist per-turn timestamps. Then introduce a relevance gate and a small episodic budget for ordinary casual turns, with tests for relevant, irrelevant, and corrected facts. Finally evaluate real multi-turn conversations across restart, `/new`, and each connected channel, scoring accuracy, naturalness, and reply length against human-reviewed expected behavior. Synthetic prompt/profile tests can prove plumbing, but cannot by themselves establish a believable long-term conversational experience.
